# Login + Dashboard UI Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build a themed (navy + muted gold) login page and dashboard page for the BMN Harwat
vehicle-maintenance app, on top of the current bare Django scaffold, with no new runtime
dependencies beyond what's already installed.

**Architecture:** A new `core` Django app holds a custom `AuthenticationForm` + login view (HTMX
form submission), a `@login_required` dashboard view rendering four mock-data blocks, and a
shared `base.html` shell (sidebar + topbar). Frontend assets (Tailwind CSS, HTMX, Alpine.js) are
built/vendored to local static files — no CDN calls in shipped HTML.

**Tech Stack:** Django 6.1.1, Python 3.14 (via `uv`), Tailwind CSS v4.3.3 (standalone CLI,
CSS-first `@theme` config), HTMX v2.0.10 (vendored), Alpine.js v3.17.4 (vendored), Django's
built-in test runner.

**Spec:** `docs/superpowers/specs/2026-09-22-login-dashboard-ui-design.md`

## Global Constraints

- Django version stays 6.1.1, Python stays 3.14 — run every Python/Django command through
  `uv run` (e.g. `uv run python manage.py test`), never bare `python`.
- No new entries added to `pyproject.toml`. Django's built-in `django.contrib.auth` covers the
  login form; no `django-widget-tweaks` or similar. `pytest` is not installed — use Django's
  built-in test runner (`manage.py test`) for every test in this plan.
- No CDN references anywhere in shipped templates. HTMX and Alpine.js are downloaded once and
  committed as local files under `static/vendor/`. Tailwind's CLI binary is downloaded to
  `bin/tailwindcss` and is **not** committed (platform-specific binary; gitignored).
- Tailwind CSS v4 uses CSS-first configuration (`@theme { ... }` inside the CSS entry file) —
  there is no `tailwind.config.js` in this plan. This supersedes the spec's mention of
  `tailwind.config.js`; the *intent* (centralized theme tokens, not hardcoded hex in templates)
  is unchanged, only the v4 mechanism differs from what the spec assumed.
- `django-bolt` (already in `INSTALLED_APPS`) is a JSON-API framework only (confirmed against
  its routing docs and installed package: `BoltAPI`/`Router` register routes in Rust's router,
  separate from Django's URLconf, and every endpoint returns JSON). It is **not used** for the
  HTML pages in this plan — login and dashboard are plain Django views wired through
  `harwat_main/urls.py` → `core/urls.py`, exactly as Django's own tutorial does it.
- Exact color tokens (from the spec, do not substitute different values):
  - `navy` = `#0B1F3A`
  - `navy-light` = `#132C4F`
  - `gold` = `#C9A227`
- No models in this plan. Dashboard data is a plain Python dict built in the view.

- [ ] **Step 3: Write the build script**

Create `scripts/build-css.sh`:

```bash
#!/usr/bin/env bash
set -euo pipefail

VERSION="v4.3.3"
BIN="bin/tailwindcss"

if [ ! -f "$BIN" ]; then
    mkdir -p bin
    ARCH="$(uname -m)"
    case "$ARCH" in
        aarch64|arm64) ASSET="tailwindcss-linux-arm64" ;;
        x86_64) ASSET="tailwindcss-linux-x64" ;;
        *) echo "Unsupported arch: $ARCH" >&2; exit 1 ;;
    esac
    curl -sL -o "$BIN" "https://github.com/tailwindlabs/tailwindcss/releases/download/${VERSION}/${ASSET}"
    chmod +x "$BIN"
fi

mkdir -p static/dist
"$BIN" -i static/src/input.css -o static/dist/output.css --minify
```

Make it executable: `chmod +x scripts/build-css.sh`

- [ ] **Step 6: Write the login view**

Create `core/views.py`:

```python
from django.contrib.auth import login as auth_login
from django.contrib.auth.decorators import login_required
from django.http import HttpResponse
from django.shortcuts import redirect, render

from .forms import LoginForm


def login_view(request):
    if request.user.is_authenticated:
        return redirect("core:dashboard")

    if request.method == "POST":
        form = LoginForm(request, data=request.POST)
        if form.is_valid():
            user = form.get_user()
            auth_login(request, user)
            request.session.set_expiry(1209600 if form.cleaned_data.get("remember_me") else 0)

            if request.headers.get("HX-Request") == "true":
                response = HttpResponse(status=204)
                response["HX-Redirect"] = "/dashboard/"
                return response
            return redirect("core:dashboard")
    else:
        form = LoginForm(request)

    return render(request, "core/login.html", {"form": form})


def logout_view(request):
    from django.contrib.auth import logout as auth_logout

    auth_logout(request)
    return redirect("core:login")


@login_required
def dashboard_view(request):
    return render(request, "core/login.html", {"form": LoginForm(request)})
```

(`dashboard_view` is a placeholder that reuses `login.html` for now — Task 4 replaces its body
