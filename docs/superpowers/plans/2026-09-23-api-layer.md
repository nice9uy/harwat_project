# External JSON API Layer (django-bolt) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Give external clients (mobile apps, other systems) a JSON API — JWT-authenticated login/refresh/logout plus full `Vehicle` CRUD and a fleet-summary endpoint — without changing a single existing Django view, template, or URL.

**Architecture:** `django-bolt` (already the project's server, `manage.py runbolt`) autodiscovers a separate `BoltAPI()` instance per Django app by scanning `INSTALLED_APPS` for `<app>/api.py`. This plan adds two: `accounts/api.py` (JWT auth routes, since `accounts` already owns Django auth) and `fleet/api.py` (Vehicle CRUD + fleet summary). `harwat_main/api.py` — the existing project-level file with its `/api/health` boilerplate — gains only the OpenAPI docs config. The one piece of logic shared between the existing HTML dashboard and the new API (the fleet-summary aggregate) is extracted into `fleet/services.py`; everything else is purely additive.

**Tech Stack:** `django-bolt` (already installed, `>=0.11.1`), its `JWTAuthentication`/`create_token_pair`/`rotate_refresh_token`/`DjangoORMRevocation` auth primitives, its `ViewSet`/`Serializer` CRUD abstractions, its `django_bolt.testing.TestClient` for API-route tests (httpx-based, requires Django's `TransactionTestCase` — see Global Constraints).

**Spec:** `docs/superpowers/specs/2026-09-23-api-layer-design.md`

## Global Constraints

- One `BoltAPI()` instance per app file (`accounts/api.py`, `fleet/api.py`), autodiscovered by `runbolt` — never import one app's `api` object into another's file.
- JWT secret is `settings.SECRET_KEY` (Django's existing secret) — no new secret to provision.
- Access tokens and refresh tokens are read from the `Authorization: Bearer <token>` header (`JWTAuthentication`'s default `header="authorization"`) — never `cookie=`, this API is for external clients, not a same-origin browser.
- Revocation store is `DjangoORMRevocation(model="accounts.RevokedToken")` — not `DjangoCacheRevocation` (Django's `CACHES` isn't wired to Valkey anywhere in this project) and not `InMemoryRevocation` (wouldn't be shared across `runbolt --processes N` worker processes in prod).
- **Any test that makes a request through a `BoltAPI` instance and touches the database MUST subclass `django.test.TransactionTestCase`, never `django.test.TestCase`.** Verified directly in the installed `django_bolt/testing/client.py`: Bolt handlers run on framework threads with their own DB connections, which cannot see rows written inside a `TestCase`'s uncommitted outer transaction — symptom is an unexplained 500 or (on SQLite) `database table is locked`.
- No change to any file under `templates/`, no change to `accounts/views.py` other than the one `fleet_summary` call-site (Task 3), no change to `accounts/urls.py`, `fleet/views.py`, `fleet/urls.py`, or `fleet/forms.py`.
- `ViewSet.perform_create`/`perform_update`'s default (`await obj.asave()`) does **not** run Django's `full_clean()`/`validate_unique()` — a duplicate `nopol` would raise a raw `IntegrityError`, which nothing in `django-bolt`'s error handling converts to a clean 4xx (confirmed: no `IntegrityError` handling in the installed `error_handlers.py`). Task 4 overrides both hooks to catch it explicitly.
- Run tests via `podman exec podman_app_1 python manage.py test <app>` — the dev stack's `app` container (bind-mounts the repo, no rebuild needed).

```python
from django.conf import settings
from django.contrib.auth import aauthenticate

from django_bolt import BoltAPI
from django_bolt.auth import (
    DjangoORMRevocation,
    JWTAuthentication,
    LoginCredentials,
    TokenRotationError,
    create_token_pair,
    rotate_refresh_token,
)
from django_bolt.exceptions import HTTPException

api = BoltAPI()

revocation_store = DjangoORMRevocation(model="accounts.RevokedToken")

refresh_auth = JWTAuthentication(
    secret=settings.SECRET_KEY,
    token_type="refresh",
    revocation_store=revocation_store,
)


@api.post("/auth/login", tags=["auth"])
async def login(request, credentials: LoginCredentials):
    user = await aauthenticate(username=credentials.username, password=credentials.password)
    if user is None or not user.is_active:
        raise HTTPException(status_code=401, detail="Invalid credentials")
    pair = create_token_pair(user, secret=settings.SECRET_KEY, method="pwd")
    return {
        "access_token": pair.access_token,
        "refresh_token": pair.refresh_token,
        "token_type": "bearer",
    }


@api.post("/auth/refresh", auth=[refresh_auth], tags=["auth"])
async def refresh(request):
    try:
        pair = await rotate_refresh_token(
            request["context"]["auth_claims"],
            store=revocation_store,
            secret=settings.SECRET_KEY,
        )
    except TokenRotationError:
        raise HTTPException(status_code=401, detail="Invalid or reused refresh token")
    return {
        "access_token": pair.access_token,
        "refresh_token": pair.refresh_token,
        "token_type": "bearer",
    }


@api.post("/auth/logout", auth=[refresh_auth], tags=["auth"])
async def logout(request):
    claims = request["context"]["auth_claims"]
    await revocation_store.revoke(claims["jti"], exp=claims.get("exp"))
    return {"detail": "Logged out"}
```

```python
from django.conf import settings
from django.db import IntegrityError

from django_bolt import BoltAPI
from django_bolt.auth import IsAuthenticated, JWTAuthentication
from django_bolt.exceptions import HTTPException
from django_bolt.serializers import Serializer, field
from django_bolt.views import ViewSet

from .models import Vehicle

api = BoltAPI()

access_auth = JWTAuthentication(secret=settings.SECRET_KEY)


class VehicleSerializer(Serializer):
    id: int = field(read_only=True)
    nopol: str
    jenis: str
    merek: str
    tahun: int
    status: str
    odometer_km: int
    penanggung_jawab: str


@api.viewset("/api/vehicles")
class VehicleViewSet(ViewSet):
    queryset = Vehicle.objects.all()
    serializer_class = VehicleSerializer
    auth = [access_auth]
    guards = [IsAuthenticated()]

    async def perform_create(self, obj):
        try:
            await obj.asave()
        except IntegrityError:
            raise HTTPException(status_code=409, detail="A vehicle with this nopol already exists")

    async def perform_update(self, obj):
        try:
            await obj.asave()
        except IntegrityError:
            raise HTTPException(status_code=409, detail="A vehicle with this nopol already exists")
```

(`perform_create`/`perform_update` are overridden identically here — both wrap the same `obj.asave()` the base `ViewSet` would otherwise call unguarded, per Global Constraints. `Vehicle.tahun`'s model-level `choices`/`PositiveSmallIntegerField` constraints and `jenis`/`status`'s `choices` still apply at `obj.asave()` time same as they do for the existing HTML form path — Django validates `choices` on `full_clean()`, not on `save()`, so an invalid `jenis`/`status` string reaches the database as-is via this path today; this matches the spec's explicit acceptance of that gap, not a new one introduced here.)

```python
from django_bolt import BoltAPI, Request
from django_bolt.openapi import OpenAPIConfig, ScalarRenderPlugin

api = BoltAPI(
    openapi_config=OpenAPIConfig(
        title="BMN Harwat API",
        version="1.0.0",
        path="/api/docs",
        render_plugins=[ScalarRenderPlugin(path="/")],
    )
)
api.mount_django("/")


@api.get("/api/health")
async def health(request: Request) -> dict:
    return {"status": "ok"}
```

(`OpenAPIConfig.path` — default `/docs` — is the *base* path every docs endpoint is mounted under; a render plugin's own `path=` is a **sub-path relative to that base**, not an absolute one. `ScalarRenderPlugin(path="/")` serves the UI at exactly `{base}/` — i.e. `/api/docs/` — and the machine-readable schema always lives at `{base}/openapi.json`, i.e. `/api/docs/openapi.json`, confirmed directly in the installed `django_bolt/openapi/routes.py`. Getting `path=` backwards — putting `/api/docs` on the plugin instead of the config — would mount the UI at `/docs/api/docs` instead, a name that happens to look plausible without being tested.)
